IP Address

IDEA-BASED ENGINEERING · 30 VISUAL CARDS · FROM FIRST PRINCIPLES

Imagine that the Internet does not exist yet. We have computers, cables and information to exchange. Our objective is to invent an addressing system ourselves, discovering each new idea only when the previous solution becomes insufficient.

Phase 01 — Inventing an identity

01 / 30 · THE ORIGINAL PROBLEM

Connecting two computers

We connect two computers using a cable. Computer A sends information, and B receives it. There is only one possible destination, so an explicit destination address is unnecessary in this simplified system.

Idea discovered

A dedicated communication channel can implicitly identify its recipient.

02 / 30 · INTRODUCING AMBIGUITY

What happens when another computer joins?

The moment multiple computers share a communication medium, the message alone is insufficient. We need information identifying its intended recipient.

New requirement

Every message needs an unambiguous way to specify its destination.

03 / 30 · THE FIRST INVENTION

Give each computer a number

Instead of sending only Hello, we attach source and destination numbers. Computer 002 recognizes its address and accepts the message.

Reusable engineering idea

Separate the information being transported from the metadata needed to deliver it.

04 / 30 · TWO KINDS OF IDENTITY

Hardware identity vs. network identity

A device can move between networks. We therefore distinguish its local link-layer identity (MAC address) from an address assigned according to its network location.

MAC address
Local link delivery
IP address
Network-layer delivery

MAC addresses can also change, for example through address randomization.

05 / 30 · STANDARDIZATION

Inventing a common addressing language

Independently designed networks cannot communicate reliably unless they agree on common addressing and packet-handling rules.

We introduce a shared network-layer protocol: Internet Protocol (IP).

Reusable engineering idea

Standardize the interface rather than requiring every underlying system to be identical.

Phase 02 — Constructing IPv4

06 / 30 · REPRESENTATION

How many bits should an address have?

Computers work with binary information. Instead of inventing arbitrary names, we represent addresses using fixed-length binary numbers.

IPv4 address length
32 bits
Address space
2³²

Not all of these values can be assigned to ordinary devices.

07 / 30 · DECOMPOSITION

Divide a long number into smaller units

A 32-bit binary sequence is difficult for humans to read and manipulate. What if we divide it into four equal groups?

Each 8-bit group is called an octet, with possible values from 0 to 255.

Reusable engineering idea

Decompose a large data representation into smaller, predictable units.

08 / 30 · HUMAN-READABLE REPRESENTATION

Inventing dotted-decimal notation

Convert each binary octet into decimal and separate the values with dots.

192.168.1.10
IPv4 dotted-decimal notation

The underlying address remains a 32-bit number.

09 / 30 · HIERARCHICAL IDENTITY

A device needs a location, not just a number

Assigning unrelated numbers to every device makes it difficult to locate them. Instead, make devices in the same network share part of their address.

Idea discovered

Hierarchical identifiers allow an enormous search space to be divided into manageable regions.

10 / 30 · ADDRESS STRUCTURE

Network portion + host portion

For 192.168.1.10/24, the first 24 bits identify the network, while the remaining 8 bits identify an address within it.

The boundary can be placed at different bit positions. This becomes the foundation of subnetting.

Phase 03 — Organizing growing networks

11 / 30 · THE SCALABILITY PROBLEM

Why flat addressing fails at scale

Imagine maintaining an individual routing entry for every computer on Earth. The routing information would grow enormously.

Instead, one routing entry can represent an entire block of addresses.

Reusable engineering idea

Aggregate individual entities into groups to reduce the amount of state a system must maintain.

12 / 30 · THE EARLY SOLUTION

Inventing classful addressing

Networks come in different sizes. An early IPv4 solution offered three fixed categories for ordinary unicast addressing.

Network bitsHost bits

This simplified allocation, but the fixed network sizes introduced a serious problem. Classful addressing is now obsolete for modern Internet routing.

13 / 30 · RESOURCE WASTAGE

Discovering the cost of fixed allocation

A company needs addresses for 1,000 computers. A Class C network is too small, so under the old fixed-class approach, it might receive a Class B network.

New requirement

Allocate address blocks according to actual demand, rather than fixed categories.

14 / 30 · BIT MASKING

Inventing the subnet mask

How does a computer extract the network portion from an IP address? We create a second binary number that marks which bits belong to the network.

The bitwise AND operation preserves the network bits and clears the host bits. This is a powerful general-purpose technique for extracting selected parts of binary data.

Phase 04 — Making independent networks communicate

18 / 30 · LOCAL DELIVERY

Can the destination be reached directly?

Before sending a packet, a computer must determine whether the destination is on its local subnet or on a remote network.

Applying the /24 mask to both addresses produces the same network address. The sender can deliver the packet over the local link without sending it through a router.

19 / 30 · ADDRESS RESOLUTION

Inventing ARP: discovering a local MAC address

The sender knows the destination IP address, but Ethernet delivery requires a destination MAC address. How can it discover the missing information?

Address Resolution Protocol (ARP) asks the local network which device owns an IPv4 address and caches the returned mapping.

Reusable engineering idea

Dynamically resolve missing metadata, then cache the result to avoid repeating discovery.

20 / 30 · DELEGATION

Inventing the default gateway

A computer cannot maintain detailed knowledge of every network on the Internet. Instead, configure a nearby router to handle destinations for which no more specific route exists.

21 / 30 · INTERCONNECTION

Build a router between independent networks

Build a device with an interface in each network. It receives IP packets on one interface, examines the destination and forwards them through an appropriate outgoing interface.

That device is a router.

Reusable engineering idea

Interconnect isolated systems using an intermediary that understands their common protocol.

22 / 30 · DECISION MAKING

Build a routing table

A router may have dozens of possible paths. We need a data structure that maps destination network prefixes to forwarding decisions.

Longest prefix matching: prefer the most specific applicable network route.

Phase 05 — Solving practical addressing problems

23 / 30 · REUSABLE ADDRESS SPACE

Invent public and private addresses

Two households should be able to use the same internal addresses without coordinating with one another.

Illustrative external addresses use documentation-only ranges.

Reserve certain address blocks for private networks. These may be reused independently, while globally routed public addresses must avoid conflicting assignments.

24 / 30 · TRANSLATION AND MULTIPLEXING

How can many devices share one public IP?

Giving every device its own public IPv4 address becomes expensive and difficult. Let the gateway translate addresses and distinguish simultaneous connections using port numbers.

Translation state

NAT translates network addresses. PAT, also called NAPT, additionally translates transport-layer port numbers so multiple devices can share an external address.

26 / 30 · LOCAL SELF-COMMUNICATION

Communicate with your own computer

Suppose we build a web server and a client on the same machine. Should their traffic travel through a physical network?

Reserve an address range that refers to the local machine. The operating system handles communication internally through a virtual loopback interface.

127.0.0.1
IPv6 loopback
::1

Applications can use normal networking interfaces even when both ends of the connection are on the same machine.

27 / 30 · NAMING AND INDIRECTION

Replace difficult numbers with meaningful names

Remembering the IP address of every website is impractical. Addresses might also change when a service moves to a different server.

https://example.com

Invent a distributed naming system that resolves names into information such as IP addresses. This is the Domain Name System (DNS).

Reusable engineering idea

Separate a stable logical name from the underlying physical or network location through indirection.

Phase 06 — Redesigning addressing for the future

28 / 30 · THE CAPACITY CEILING

Discovering IPv4 address exhaustion

Our original 32-bit design seemed enormous. But computers, smartphones, servers, cloud infrastructure and connected devices continue to increase demand.

THE ENTIRE IPv4 ADDRESS SPACE
4,294,967,296
Maximum theoretical number of distinct addresses

CIDR reduces allocation waste. NAT allows address sharing. But neither increases the total number of possible IPv4 addresses.

Fundamental design limitation

Optimizing a fixed-capacity system cannot permanently eliminate its capacity ceiling.
