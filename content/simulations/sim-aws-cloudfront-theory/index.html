Part 1 — Fundamentals

01 / 25

What is Amazon CloudFront?

Amazon CloudFront is AWS's Content Delivery Network (CDN). It delivers pages, images, videos, files and API responses through a worldwide network of servers. Its purpose is faster content delivery, reduced origin workload and improved security.

02 / 25

What is a CDN?

A CDN stores temporary copies of frequently requested content at distributed locations. Like a book publisher with local distribution centers instead of one warehouse, CloudFront caches eligible files as users request them.

04 / 25

CloudFront global infrastructure

CloudFront is a global service. The origin may exist in a single Region while users access content through distributed edge infrastructure. Requests are generally directed to an edge location that can serve them with low latency.

Schematic map, not an inventory of actual sites.

05 / 25

What is an Edge Location?

An edge location or Point of Presence (PoP) handles requests close to users and can return cached content without contacting the origin. Edge locations are optimized for network delivery, not general EC2 application hosting.

06 / 25

Regional Edge Caches

Regional edge caches act as a larger intermediate caching layer shared by multiple edge locations. An edge miss may be satisfied here instead of at the origin. Certain requests bypass this layer.

Part 2 — Caching & Request Processing

09 / 25

Complete request-response lifecycle

  1. Browser requests an image through the CloudFront domain.
  2. Edge searches its cache.
  3. If required, CloudFront checks regional cache.
  4. Origin returns the image.
  5. Eligible responses are cached and delivered.

Later requests for the same fresh cached image can be served without contacting the origin.

What is a Cache Key?

awsCache key
Policy includesPath + size + color
Entry A/shirt.png?color=red
Entry B/shirt.png?color=blue

A cache key identifies a particular cached response. Configured request attributes help differentiate variants. Including color avoids mixing different images; including irrelevant parameters can reduce cache hit ratio.

12 / 25

Time to Live (TTL)

Original TTL: 60 minutes

Cached 15 minutes ago; response still fresh.

Cache-Control: max-age=3600

TTL controls how long a cached object remains fresh. The example specifies one hour, subject to the cache policy. Objects may be evicted earlier. After expiry, CloudFront can revalidate or fetch updated content.

13 / 25

Cache Invalidation

When a new logo is uploaded, an old cached logo may still be served. Invalidation tells CloudFront to remove specified cached content; it takes time to propagate.

Versioned filenames are useful for CSS, JavaScript and images because each version has a different cache key.

An analytics header that does not change the image can be forwarded without including it in the cache key. Attributes selected by the cache policy are automatically included in origin requests too.

Static content is typically identical across requests. Dynamic content is generated or customized by the backend. CloudFront can accelerate both, but personalized responses must not be shared between users by unsafe caching.

16 / 25

Origin Shield

Origin Shield is an optional centralized caching layer that consolidates upstream requests. Thousands of requests for the same new video can cause fewer repeated origin requests. Useful for expensive origins, streaming and multi-CDN architectures; may add cost and some requests bypass it.

Part 3 — Security

17 / 25

HTTPS, SSL and TLS Certificates

awsCustom domain certificate
Domainshop.example.com
ServiceAWS ACM
ACM Region for CloudFrontus-east-1

HTTPS encrypts communication using TLS. CloudFront terminates viewer TLS and can establish a separate HTTPS connection with the origin. An ACM certificate for a CloudFront custom domain must be in Northern Virginia, even for an application in Mumbai.

18 / 25

Origin Access Control (OAC)

Access routeResult
User → CloudFront → S3Allowed by configured policy
Anonymous → private S3Denied

OAC authenticates CloudFront requests to a private S3 origin. Configure bucket policy permissions while keeping public access blocked. OAC protects the origin; it does not automatically make the distribution private to viewers. It is recommended over OAI for supported origins.

19 / 25

21 / 25

Geographic Restrictions

A streaming company might have rights in the US and India only. Geographic restrictions allow or deny based on detected viewer country. Disallowed viewers generally receive HTTP 403. IP-derived location is not a perfect indicator of a person's actual location.

Origin Failover

Supported methodsNot supported for failover
GET · HEAD · OPTIONSPOST · PUT · PATCH · DELETE

If an eligible request to the primary fails with a configured condition, CloudFront can retry the secondary. Useful for read-heavy media. It does not replicate data or fail over write requests; payment systems need separate recovery strategies.

Real-World Global Video Streaming Architecture

  1. Streaming application verifies the subscription.
  2. Application provides signed cookies.
  3. Player requests a manifest and media segments.
  4. CloudFront serves cached segments or fetches missing ones.
  5. Player buffers segments and adapts quality.
  6. Origin failover can retrieve eligible content from recovery storage.

Adaptive bitrate streaming

CloudFront delivers video segments efficiently; the player chooses quality. Encoding, subscription management and DRM are handled by other components.
