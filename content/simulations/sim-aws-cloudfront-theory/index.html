Part 1 — Fundamentals

01 / 25

What is Amazon CloudFront?

Amazon CloudFront is AWS's Content Delivery Network (CDN). It delivers website pages, images, videos, files and API responses through a worldwide network of servers.

Its main purpose is to make content delivery faster, reduce origin server workload and improve security.

02 / 25

What is a CDN?

A CDN stores temporary copies of frequently requested content at distributed locations.

Imagine a book publisher with one central warehouse. Instead of shipping every book internationally, it places popular books in local distribution centers.

CloudFront applies the same concept to digital content, caching eligible files as users request them.

CloudFront global infrastructure

● Edge locations   ▪ Origin server

CloudFront is a global service. Your origin might exist in a single AWS Region, while users access content through geographically distributed edge infrastructure.

Requests are generally directed to an edge location that can serve them with low latency.

05 / 25

What is an Edge Location?

An edge location, also called a Point of Presence (PoP), is a network site that handles requests close to users.

It can return cached content without contacting the original application server.

Edge location ≠ Availability Zone. An edge location is optimized for network delivery, rather than general EC2 application hosting.

06 / 25

Regional Edge Caches

Regional edge caches act as a larger intermediate caching layer shared by multiple edge locations.

If a file is missing from an edge cache, CloudFront may retrieve it from a regional edge cache instead of contacting the origin.

This improves the probability of finding cached content. Certain requests bypass this intermediate layer.

Part 2 — Caching & Request Processing

09 / 25

Complete request-response lifecycle

  1. Browser requests an image through the CloudFront domain.
  2. Edge searches its cache.
  3. If required, CloudFront checks regional cache.
  4. Origin returns the image.
  5. Eligible responses are cached and delivered.

Later requests for the same fresh cached image can be served without contacting the origin.

A hit means CloudFront finds a usable cached response. A miss means it needs to retrieve the response from an upstream cache or origin.

Higher hit ratios generally reduce origin workload.

11 / 25

What is a Cache Key?

A cache key identifies a particular cached response. CloudFront uses the requested path and configured request attributes to look up that response.

/shirt.png?color=redCache entry A
/shirt.png?color=blueCache entry B

Including the color parameter prevents CloudFront from confusing two different product images.

Including unnecessary parameters can create excessive cache entries and reduce the hit ratio.

12 / 25

Time to Live (TTL)

Original TTL: 60 minutes

Cached for 15 minutes. The response is still considered fresh.

Cache can serve the file

Cache-Control: max-age=3600

TTL controls how long a cached object remains fresh. This example specifies 3,600 seconds, or one hour, subject to the CloudFront cache policy.

CloudFront may evict an object before its TTL expires. After expiry, it can check the origin for updates, including through conditional requests.

13 / 25

Cache Invalidation

Suppose your company uploads a new logo, but CloudFront still serves the old cached logo.

Invalidation tells CloudFront to remove the specified cached content so a subsequent request can retrieve the updated version. It takes time to propagate.

Alternative: File versioning
logo-v1.png
Old version
logo-v2.png
New version

Versioned filenames are especially useful for JavaScript, CSS and images because each new version has a different cache key.

An analytics header that does not change the image can be forwarded without including it in the cache key. Attributes selected by the cache policy are automatically included in origin requests too.

Static vs Dynamic Content

Static contentSame files for many users
Dynamic contentResponse depends on the user
ContentTypical caching
Product imagesLong TTL
Versioned CSS/JSLong TTL
Public catalogShort TTL

Static content is typically identical across requests. Dynamic content is generated or customized by the backend. CloudFront can accelerate both, but personalized responses must not be shared between users by unsafe caching.

16 / 25

Origin Shield

Origin Shield is an optional centralized caching layer that helps consolidate upstream requests.

Imagine thousands of customers request the same new video from different continents. Origin Shield can reduce repeated requests for that video reaching your backend.

It is especially useful for expensive origin processing, video streaming and applications using multiple CDNs. It may add cost and some requests bypass the additional layer.

Part 3 — Security

HTTPS, SSL and TLS Certificates

awsCustom domain certificate
Domainshop.example.com
ServiceAWS ACM
ACM Region for CloudFrontus-east-1

HTTPS encrypts communication using TLS. CloudFront terminates viewer TLS and can establish a separate HTTPS connection with the origin. An ACM certificate for a CloudFront custom domain must be in Northern Virginia, even for an application in Mumbai.

18 / 25

Origin Access Control (OAC)

Access routeResult
User → CloudFront → S3Allowed by configured policy
Anonymous → private S3Denied

OAC authenticates CloudFront requests to a private S3 origin. Configure bucket policy permissions while keeping public access blocked. OAC protects the origin; it does not automatically make the distribution private to viewers. It is recommended over OAI for supported origins.

21 / 25

Geographic Restrictions

✓ Allowed   × Restricted

Imagine a streaming company has distribution rights for a movie in the United States and India, but not other countries.

CloudFront geographic restrictions allow or deny access based on the viewer's detected country.

Disallowed viewers generally receive an HTTP 403 Forbidden response. This is useful for licensing and territorial content restrictions, but is not a perfect method of identifying a person's actual location.

CloudFront Functions vs Lambda@Edge

■ CloudFront Functions   ■ Lambda@Edge

Edge computing allows developers to execute application logic during CloudFront request processing, rather than always sending requests to a central backend.

CloudFront FunctionsLambda@Edge
Lightweight JavaScriptJavaScript or Python runtimes

Very short executionSupports more complex processing

Example: URL rewriting
Incoming URL/products/↓ CloudFront Function/products/index.html

The function rewrites the request at the edge before CloudFront looks up the content.

Choose between the two services based on trigger requirements, runtime capabilities and complexity.

Origin Failover

Supported methodsNot supported for failover
GET · HEAD · OPTIONSPOST · PUT · PATCH · DELETE

If an eligible request to the primary fails with a configured condition, CloudFront can retry the secondary. Useful for read-heavy media. It does not replicate data or fail over write requests; payment systems need separate recovery strategies.

Real-World Global Video Streaming Architecture

  1. Streaming application verifies the subscription.
  2. Application provides signed cookies.
  3. Player requests a manifest and media segments.
  4. CloudFront serves cached segments or fetches missing ones.
  5. Player buffers segments and adapts quality.
  6. Origin failover can retrieve eligible content from recovery storage.

Adaptive bitrate streaming

CloudFront delivers video segments efficiently; the player chooses quality. Encoding, subscription management and DRM are handled by other components.
