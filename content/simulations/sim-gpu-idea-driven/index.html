GPU — Recreating the invention

Idea-Driven Learning · 25 cards · First-principles engineering

Imagine GPUs have never been invented. We have a computer, a screen and a problem to solve. Every invention we make will emerge from a limitation in our previous solution.

This is our own engineering reconstruction, not a literal history of GPU development.

Phase 1 — Birth of the idea

IDEA 01 / 25

How can a computer draw an image?

A computer understands numbers, not mountains, sunlight or colors.
Our first problem: How do we convert a picture into something a machine can calculate?
IDEA 02 / 25

Break the picture into tiny squares

What if we divide the entire picture into small addressable squares and control each square independently?
Invention: Pixels and raster images.
IDEA 03 / 25

Turn colors into mathematics

Represent each pixel using three numbers. Changing those numbers changes its color.
(255,128,0) → (127,64,0)Multiply by 0.5 to darken the pixel.
Invention: Image manipulation through arithmetic.
IDEA 04 / 25

Our computer is becoming too slow

Full HD screen2.07MPixels per frame
At 60 frames/sec124.4MPixel updates/sec
Even a simple effect applied to every pixel creates a huge workload.
Problem: Processing everything sequentially does not scale well.
IDEA 05 / 25

What if we calculate simultaneously?

If changing one pixel doesn't depend on another pixel, why calculate them one at a time?
Invention: Data parallelism.
Idealized experiment: four workers provide 4× throughput when work is independent and overhead is zero.

Phase 2 — Inventing a new processor

IDEA 06 / 25

Build multiple calculation units

Instead of buying four complete CPUs, what if we place four arithmetic units inside one processor? Each unit processes different data simultaneously.
Invention: Multiple parallel execution units.
IDEA 07 / 25

Sacrifice complexity for quantity

For repetitive mathematics, we don't necessarily need every execution unit to make complicated independent decisions. Allocate more chip area to arithmetic and share some control resources.
Invention: Throughput-oriented processor architecture.
Conceptual chip layout, not a physical CPU or GPU blueprint.
IDEA 08 / 25

Give one instruction to many workers

Why decode the same instruction separately for every calculation? Share instruction control among workers performing similar operations.
Invention: SIMD-style execution, leading toward SIMT architectures.
Modern GPU threads can have individual state while executing in scheduled groups.
IDEA 09 / 25

Divide a huge problem into independent tasks

Divide an image into regions. Assign each region to a group of workers rather than managing millions of pixels individually.
Invention: Tiling and grouped parallel workloads.
IDEA 10 / 25

Organize thousands of workers

A single controller managing thousands of individual workers would become difficult to scale. Build reusable clusters, each containing execution units, scheduling logic and nearby storage.
Invention: Streaming multiprocessor-style architecture.

Phase 3 — Solving the problems our invention created

IDEA 11 / 25

How do we feed thousands of hungry workers?

We built more processors, but they cannot calculate without receiving data. Adding workers alone won't solve the problem.
New insight: Computing power is useless without sufficient data delivery.
IDEA 12 / 25

Build a wider road for data

Rather than transferring small amounts of data repeatedly, move many values together and use multiple memory channels.
Invention: High-bandwidth memory systems.
The next challenge is arranging data so adjacent workers can access it efficiently.
IDEA 13 / 25

Stop fetching the same data repeatedly

If multiple workers need the same value, fetch it once and keep a reusable copy close to them.
Invention: Shared on-chip memory and data reuse.
IDEA 14 / 25

Don't sit idle while waiting for data

When group A requests data and must wait, give the execution units to group B, C or D until A becomes ready again.
Invention: Latency hiding through hardware scheduling.
Waiting still occurs; useful independent work overlaps it.
IDEA 15 / 25

What if workers disagree about the next instruction?

Shared instruction execution becomes less efficient when some workers take one branch and others take another. Execute the required paths with their corresponding workers active.
Discovery: Branch divergence.
Where possible, organize similar work together. Parallelism does not automatically guarantee speed.

Phase 4 — Discovering that our invention can do more

IDEA 16 / 25

Are we really processing pictures?

Our hardware doesn't inherently understand pictures. It processes numbers representing pictures. What if we replace those pixel values with temperatures, prices, distances or probabilities?
Breakthrough: The invention is not limited to graphics.
IDEA 17 / 25

Remove the graphics restriction

Make the execution units programmable and allow software developers to choose their own calculations rather than only graphics operations.
Invention: General-purpose computing on graphics processors (GPGPU).
IDEA 18 / 25

Discover a mathematical workload that fits perfectly

Each output element can be computed from a row and a column. Different output elements can be calculated concurrently.
Matrix size1,000 × 1,000
Multiplications required1 billion
Discovery: Matrix multiplication is an excellent candidate for parallel hardware.
IDEA 19 / 25

Invent hardware specifically for matrix calculations

We keep multiplying and accumulating values. Instead of treating every operation separately, build a specialized unit that accelerates entire groups of these calculations.
Invention: Dedicated matrix acceleration hardware.
Examples include tensor cores and matrix engines. MAC means multiply–accumulate; this diagram is conceptual, not a literal tensor-core circuit.
IDEA 20 / 25

Connect our invention to artificial intelligence

Neural networks repeatedly combine input values with weights. Much of this computation can be expressed as matrix operations. The engine we originally invented to draw images can now accelerate AI.
Breakthrough: Graphics hardware evolves into an AI computing platform.

Phase 5 — Transfer the idea to other inventions

IDEA 21 / 25

Can we simulate an entire physical world?

Divide a physical environment into cells. Calculate how heat moves between neighboring cells simultaneously, then repeat for the next time step.

New applications: Weather prediction, fluid dynamics, climate modeling and scientific simulations.

Transferable idea: Convert physical space into parallel numerical tasks.
IDEA 22 / 25

Can we search millions of database records together?

A condition can be evaluated across many records concurrently. Matching values can then be collected into a result.

New applications: Analytical databases, large-scale filtering and vector similarity search.

Transferable idea: Apply one operation across an entire dataset.
Best suited to sufficiently large, parallel workloads; not every database operation benefits.
IDEA 23 / 25

Can we build a machine that generates language?

Represent language numerically. Process those representations through neural networks using our parallel mathematical engine.

New application: Large language models.

Transferable idea: Complex intelligence can involve enormous amounts of parallel arithmetic.
Individual token-generation steps remain sequential in ordinary autoregressive decoding; computations within a step can be parallelized.
IDEA 24 / 25

What if one GPU is not enough?

Divide a larger problem among multiple GPUs and build communication paths so they can exchange partial results. But now our original memory bottleneck reappears as a communication bottleneck between devices.
Invention: Distributed accelerated computing.
The same ideas of partitioning, locality and communication now apply at machine scale.
IDEA 25 / 25

Now invent something beyond the GPU

Instead of asking how to use an existing processor, ask what kind of processor a particular problem deserves. Find repetitive operations. Identify independent work. Specialize the hardware. Minimize unnecessary movement of data.
You now possess an idea that can be used to design entirely new computing architectures.
