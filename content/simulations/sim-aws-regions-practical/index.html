02 / 20 · Terminal

Configuring the AWS CLI Region

$ aws configure set region ap-south-1
$ aws configure get region
ap-south-1

The CLI sends regional requests to Mumbai by default. Override the Region for a single command:

aws ec2 describe-instances --region us-east-1

Authenticate with AWS credentials or an authenticated session before making service requests.

This assumes suitable default networking and permissions. Specify VPC subnet, security group and IAM role for production. Launching resources may incur charges; terminate unused instances and check storage.

04 / 20 · Resource discovery

Why is my EC2 instance missing?

Mumbai · ap-south-11Instance found
Virginia · us-east-10No instances

You deployed the backend in Mumbai, but selected Virginia in the console. EC2 resource listings are scoped to a Region and account. An empty list does not necessarily mean your server was deleted.

05 / 20 · Application development

Configuring the Region in Java

import software.amazon.awssdk.regions.Region;
import software.amazon.awssdk.services.s3.S3Client;

S3Client s3 = S3Client.builder()
    .region(Region.AP_SOUTH_1)
    .build();

The SDK uses the configured Region to select the service endpoint. A portable deployment can use its default Region provider chain:

export AWS_REGION=ap-south-1

Avoid hardcoding the Region throughout your application.

11 / 20 · High availability

Deploying across multiple Availability Zones

  1. Create subnets in two AZs.
  2. Deploy EC2 in each AZ.
  3. Configure ALB health checks and target group.
  4. Enable RDS Multi-AZ.

ALB can redirect traffic to healthy servers. An RDS Multi-AZ DB instance standby provides failover, not an additional read-serving instance. Use the RDS endpoint to reconnect.

12 / 20 · Storage replication

Configuring S3 Cross-Region Replication

awsS3 / Management / Replication rules
Rulemumbai-to-hyderabad
StatusEnabled
DestinationHyderabad bucket
IAM roleReplication role
ScopeEligible objects

Enable versioning on both buckets and configure replication permissions. Eligible new objects copy asynchronously. Existing objects are not automatically copied by a new live rule; use S3 Batch Replication.

13 / 20 · Server migration

Copying an EC2 AMI to another Region

aws ec2 copy-image \
  --source-region ap-south-1 \
  --source-image-id ami-SOURCE_ID \
  --region ap-south-2 \
  --name shopping-backend

Wait until the copied AMI is available and launch a new instance. The destination AMI has its own ID. Configure subnets, security groups and other regional dependencies separately. An AMI copy is not live migration or continuous synchronization.

14 / 20 · Database migration

Moving an RDS database to another Region

  1. Create an RDS snapshot in Mumbai.
  2. Copy to Hyderabad.
  3. Restore a database from the copy.
  4. Validate data and update application connection.
Old endpointNew endpoint
shop-db.…ap-south-1.rds.amazonaws.comshop-db.…ap-south-2.rds.amazonaws.com

Snapshot migration restores data captured at snapshot time. Pause writes or synchronize later changes before cutover. For lower downtime, evaluate AWS DMS change data capture or supported replicas.

16 / 20 · Disaster recovery

Recovering from an entire Region failure

RTO target10 minRecovery time
RPO target1 minData-loss window

Prepare a smaller functioning copy in Hyderabad. Promote the recovery database, scale up compute, validate and switch traffic. This is Warm Standby. Recovery objectives must be tested; example timings are not guarantees.

17 / 20 · Security and compliance

Keeping sensitive data within approved Regions

Suppose customer data must be stored and processed only in India.

  1. Allow approved Mumbai and Hyderabad deployments.
  2. Restrict unauthorized backups and replication.
  3. Review logs, AI inference and encryption key locations.

AWS Organizations SCPs can restrict many operations using aws:RequestedRegion. Region restrictions alone do not guarantee residency. Audit global services, cross-Region behavior and external transfers.
