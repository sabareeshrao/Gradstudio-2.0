Redis — A visual guide

15 educational cards · Redis red and charcoal theme · Static SVG diagrams

01 / FOUNDATIONS

What is Redis?

Redis is an in-memory data structure server that stores information under unique keys. It is commonly used as a cache, database and messaging system. Its working dataset normally lives in RAM, with optional persistence to disk.

02 / PERFORMANCE

Why Redis is fast

Redis normally retrieves values directly from memory, avoiding disk reads on ordinary key lookups. Conventional databases also cache data in RAM, but Redis is designed around an in-memory working dataset.

03 / INTERNAL STORAGE

How Redis finds a key

Redis uses hash tables to locate keys efficiently. A hash function identifies the relevant bucket, where Redis searches for the matching key and retrieves its value. A simple key lookup takes O(1) time on average.

04 / DATA STRUCTURES

Six important Redis data types

Strings store values and counters; hashes represent records; lists hold ordered sequences; sets store unique members; sorted sets rank members by score; streams retain ordered events. Redis provides specialized commands for each data structure.

05 / CACHING

Cache hit and cache miss

In the cache-aside pattern, the application checks Redis first. If the key is missing, it queries the primary database and caches the result. Later requests can reuse the cached value until it expires or is invalidated.

06 / EXECUTION ENGINE

The Redis event loop

Redis primarily executes ordinary commands sequentially on its main thread while handling many client connections. Other threads can assist with networking and background work. Long-running commands can delay subsequent commands.

07 / KEY LIFECYCLE

TTL — Automatic expiration

Time to Live (TTL) defines how long a key remains valid. Redis checks expiration when keys are accessed and also periodically removes expired keys. TTL is useful for temporary sessions, verification codes and cached responses.

08 / MEMORY MANAGEMENT

What happens when memory fills up?

When Redis reaches its configured memory limit, its eviction policy determines what to remove. LRU favors removing least recently used keys; LFU favors least frequently used keys. These policies are approximate. With noeviction, memory-growing writes can be rejected.

09 / DURABILITY

RDB snapshots and AOF persistence

RDB creates point-in-time snapshots of the dataset. AOF records writes for recovery. Redis can use either mechanism, both, or neither. The amount of data that can be lost after a crash depends on persistence settings.

10 / NETWORK PERFORMANCE

Pipelining reduces network round trips

Pipelining allows a client to send multiple commands without waiting for each response. Redis returns the results in order, reducing network waiting overhead. Pipelining by itself does not provide transaction isolation.

11 / TRANSACTIONS

Executing a group of commands

MULTI queues commands and EXEC executes them without other clients interrupting the group. Redis does not automatically roll back commands after runtime errors. WATCH supports optimistic concurrency control.

12 / MESSAGING

Pub/Sub versus Streams

Pub/Sub broadcasts live messages to connected subscribers without retaining them for offline clients. Streams retain events until removed or trimmed, support consumer groups, and allow consumers to acknowledge processing and replay events.

13 / HIGH AVAILABILITY

Replication and Sentinel failover

Replicas copy the primary dataset. Sentinel monitors non-clustered Redis deployments and coordinates failover by promoting a replica when necessary. Asynchronous replication means a failover can lose recently acknowledged writes.

14 / HORIZONTAL SCALING

Redis Cluster and hash slots

Redis Cluster divides the keyspace into 16,384 hash slots. Each primary owns a subset of these slots. Cluster-aware clients route commands to the appropriate node, distributing memory usage and command processing across machines.

15 / COMPLETE ARCHITECTURE

How the Redis subsystems fit together

Redis combines network communication, a command execution engine, efficient data structures, memory management and optional persistence. Replication and clustering extend this architecture to support availability and horizontal scaling.
