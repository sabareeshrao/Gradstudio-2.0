Functional Programming — Software Architecture

Functional programming (FP) is a programming paradigm that builds software by composing functions, favoring immutable data and minimizing side effects and shared mutable state.

Instead of continuously modifying existing data, functions receive inputs and produce new outputs.

2. Imperative vs functional programming

Imagine calculating the total price of three products.

Imperative programming
Describe how to perform the work.
Changes an accumulator repeatedly.
Functional programming
Describe the desired transformation.
Transforms values into a result.
Imperative style
javascript
let total = 0;

for (const price of prices) {
  total += price;
}
Functional style
javascript
const total = prices.reduce(
  (sum, price) => sum + price, 0
);

Both achieve the same result. The functional version expresses the aggregation without reassigning a shared accumulator.

4. What is immutability?
Immutability means that once a value is created, it is not modified. Instead, changes produce a new value.

Immutable approach
javascript

The second approach preserves the original object. Object spreading creates a shallow copy, not a deeply immutable object.

Reading the current time or generating a random number also makes a function impure when its result depends on those external inputs.
Architectural principle: Side effects are necessary in real applications. Functional programming encourages keeping them explicit and controlled.

10. Referential transparency
An expression is referentially transparent when it can be replaced with its value without changing the observable behavior of the program.
The observable result is unchanged.
This property helps developers reason about code, optimize computations and safely reuse results.
11. Currying, closures and recursion
Currying
Transforms a function with multiple arguments into a sequence of functions accepting one argument at a time.
javascript
const add = a => b => a + b;

const addTen = add(10);

addTen(5); // 15
Closure
A function retains access to variables in its lexical environment.
addTen remembers a = 10. Closures can also capture mutable state, so not every closure is pure.
Recursion
A function calls itself with a smaller problem until it reaches a base case.
javascript
const factorial = n =>
  n <= 1 ? 1 : n * factorial(n - 1);

factorial(4); // 24
Example assumes non-negative integers. Deep recursion may cause stack overflow.

13. Real-world microservice example
Consider an order processing microservice.
Order service execution
Example functional business logic:
javascript
function calculateTotal(order) {
  return order.items.reduce(
    (total, item) =>
      total + item.price * item.quantity,
    0
  );
}
Imperative orchestration:
javascript
async function processOrder(order) {
  const total = calculateTotal(order);

  const updatedOrder = {
    ...order,
    total,
    status: "CONFIRMED"
  };

  await repository.save(updatedOrder);

  return updatedOrder;
}
The pure calculation can run independently of the database. The simplified orchestration omits production concerns such as validation, transactions and retries.

22. Software architect interview answer
Functional programming is a programming paradigm that treats computation as the evaluation and composition of functions. It emphasizes pure functions, immutable data, referential transparency and controlled side effects.
From a software architecture perspective, these principles improve testability, predictability, maintainability and concurrency safety.
A practical implementation is the Functional Core, Imperative Shell pattern, where business logic is kept pure while database operations, network calls and other external interactions are isolated at the system boundaries.
Functional programming can be combined with other programming paradigms to build reliable enterprise applications.
